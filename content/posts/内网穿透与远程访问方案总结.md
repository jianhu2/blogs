# 内网穿透与远程访问方案总结

整理一下常用的内网穿透 / 远程访问方案，按 “是否需要公网 IP / 协议范围 / 部署难度” 做了归类。文末是个人当前在用的组合和对比体感，给选型当个参考。

## TL;DR — 当前在用：ZeroTier + RDP

- **组网**：ZeroTier，自建 moon node
- **远程桌面**：直接走 Windows 原生 RDP（在 ZeroTier 虚拟网里，等同于同一局域网）
- **核心结论**：在两端都接入同一**自建节点**的前提下，ZeroTier 比 Tailscale 明显更流畅 —— 这是当前选 ZeroTier 的主要原因

下面按五类整理。

---

## 一、公网直连类

适用场景：家里宽带能拿到公网 IP（v4 或 v6），追求最低延迟。

| 方式 | 特点 | 是否需要公网 IP | 备注 |
| --- | --- | --- | --- |
| IPv6 直连 | 无需任何工具，直接用 IPv6 地址 | 需要家里公网 IPv6 | 现在很多家庭宽带已有 IPv6，值得优先尝试。速度和稳定性极佳 |
| 纯 IPv4 端口转发 | 传统路由器 DMZ 或端口映射 | 需要家里公网 IPv4 | 最原始方式 |

> **短评**：能直连就别走中转，少一层就少一份延迟和故障点。先验下家里宽带有没有 IPv6（运营商默认开通的越来越多），有就直接 AAAA 解析，零成本。

---

## 二、虚拟局域网 / VPN 类

把所有设备组成一个加密的虚拟局域网，像在同一个局域网里一样访问。安全性高，支持任意协议（RDP、SSH、HTTP、数据库等）。

| 工具 | 难度 | 特点 | 是否需要公网 IP |
| --- | --- | --- | --- |
| **Tailscale**（商业，有免费额度） | 极低 | 几乎零配置、速度快、跨平台优秀 | 不需要 |
| **EasyTier**（自建） | 低 | 高性能 P2P 组网、去中心化、轻量、NAT 穿透强 | 不需要（可选公共节点） |
| **WireGuard**（自建） | 低 | 性能最强、轻量、现代协议 | 需要服务器公网 IPv4 |
| **Headscale**（自建） | 中 | Tailscale 的开源自托管版 | 需要服务器公网 IPv4 |
| **ZeroTier**（商业，有免费额度） | 低 | 简单易用、支持自定义网段 | 不需要 |
| **OpenVPN**（自建） | 中 | 老牌、兼容性好 | 需要服务器公网 IPv4 |

> **个人实测**：
> - Tailscale 和 ZeroTier 都自建过节点（DERP / moon node）。在两端都接入同一自建节点的情况下，**ZeroTier 明显更流畅**，这也是当前选 ZeroTier 的主要原因。
> - Tailscale 的零配置接入仍然是它的杀手锏，临时拉一台新机入网几秒就上线；只是国内默认用官方 DERP 中转性能不稳，自建 DERP 又要持续维护。
> - **当前选择：ZeroTier（自建 moon）**。

---

## 三、内网穿透类

通过公网服务器做中转，把内网端口映射出去，支持 TCP/UDP，可用于 RDP、SSH、Web、数据库等任意服务。

| 工具 | 类型 | 难度 | 特点 | 是否需要公网 IP |
| --- | --- | --- | --- | --- |
| **frp**（自建） | 自建 | 中 | 灵活、支持 TCP/UDP/HTTP/HTTPS | 需要服务器公网 IPv4 |
| **SakuraFrp**（公共服务） | 公共服务 | 低 | frp 的公共服务版，免费额度较高 | 不需要 |
| **花生壳**（商业服务） | 商业服务 | 极低 | 稳定、合规、有技术支持、安全功能多 | 不需要 |
| **ngrok**（公共/自建） | 公共/自建 | 低 | 官方支持好，但免费版有限制 | 不需要 |
| **NPS**（自建） | 自建 | 中 | 类似 frp，Web 管理界面更友好 | 需要服务器公网 IPv4 |

> **个人实测**：
> - frp 用过，配置写起来略繁琐但跑起来稳定，作为单点端口暴露够用。
> - 切到 ZeroTier 组网之后基本不再用 —— VPN 类方案天然替代了 “端口级映射” 的需求场景。
> - 如果只是临时把某个服务暴露给外部一两个人用，frp / ngrok 仍是最快的方案。

---

## 四、仅 Web 服务

| 工具 | 难度 | 特点 | 是否需要公网 IP | 适合场景 |
| --- | --- | --- | --- | --- |
| **Cloudflare Tunnel**（商业，有免费额度） | 低 | 免费、自动 HTTPS + CDN | 不需要 | Web 服务首选 |

> **个人实测**：
> - 用的是免费版，配置极简：装个 cloudflared，登录 Cloudflare 账号、绑定域名、起 tunnel，几条命令就能把内网 Web 暴露出来，自动 HTTPS、不用自建任何节点。
> - **流畅性一般** —— 流量需要绕到 Cloudflare 边缘再回源，对国内访问者尤其能感觉到首字节延迟。带宽够用，但低延迟交互场景（实时控制、长轮询）能感觉到额外开销。
> - 适合 “低频 / 中等流量的 Web 暴露”，不适合做高交互或大文件传输。注意只支持 HTTP/HTTPS，跑不了 RDP/SSH 这类纯 TCP 服务。

---

## 五、专用远程桌面工具

| 工具 | 类型 | 是否需要公网 IP | 连接原理 |
| --- | --- | --- | --- |
| **RDP**（原生） | 直连协议 | 需要直连 | 直连 |
| VNC | 直连协议 | 需要直连 | 直连 |
| **RustDesk**（自建中继 / 公共服务） | 自建 / 公共 | 不需要（自建中继需服务器） | 中继 + P2P |
| 向日葵（商业服务） | 商业服务 | 不需要 | 云中继 |
| ToDesk（商业服务） | 商业服务 | 不需要 | 云中继 |
| AnyDesk（商业服务） | 商业服务 | 不需要 | 云中继 |
| TeamViewer（商业服务） | 商业服务 | 不需要 | 云中继 |
| UU 远程（商业服务） | 商业服务 | 不需要 | 云中继 |

> **个人实测**：
> - RustDesk 用过，自建中继可行，跨平台支持也不错。
> - 但日常更倾向 “VPN 组网 + 原生 RDP” —— Windows 原生 RDP 协议在画面流畅度和输入响应上明显更跟手。
> - 商业方案（向日葵 / ToDesk / AnyDesk）零配置、跨平台，免费版多少有限速或会话时长限制，重度使用建议付费版或自建中继方案。
> - **当前选择：ZeroTier 组网 + 原生 RDP**。

---

## 决策表：怎么选？

| 你的需求 | 推荐方案 |
| --- | --- |
| 家里有公网 IPv4 / IPv6 | 直接端口映射 / IPv6 直连 |
| 想把多台机器组成虚拟局域网（多协议、长期用） | **ZeroTier**（自建 moon）/ Tailscale（零配置场景） |
| 只暴露一个 Web 服务给外网 | **Cloudflare Tunnel** |
| 临时把某个 TCP/UDP 服务暴露给少数人 | frp / ngrok |
| 远程桌面长期高频使用 | VPN 组网 + 原生 RDP |
| 远程帮亲友修电脑、一次性支援 | 向日葵 / ToDesk |

---

## 总结

- 能直连不中转，能 VPN 不端口映射，能原生协议不三方桌面。
- 同一档自建条件下，**ZeroTier 比 Tailscale 流畅**；零配置场景 Tailscale 仍然好用。
- Web 单点暴露，**Cloudflare Tunnel** 几乎没有更好的选择。
